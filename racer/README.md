# Racer

A Blur-style arcade racer for iPhone Safari. Godot 4.7.2 (standard build, GL Compatibility renderer), single player, 8 cars, a dusk-city track, four power-ups. Personal project, not for release.

## Run, test, export

```bash
godot --headless --path racer --import                       # once on a fresh checkout
godot --headless --path racer -- --selftest                  # headless simulation + checks
cp racer/tools/export_presets.template.cfg racer/export_presets.cfg
godot --headless --path racer --export-release "Web" build/racer/index.html
```

`--selftest` runs a full three-lap AI race without rendering and checks: every car finishes, cars stay on the track, items are collected and used, the input buttons reach the player's car, and every car spec loads with a four-wheel model and sane handling. It cannot judge how the game looks or feels; that is judged by playing it.

The web preset has threading off (iOS Safari needs that). Serve the build over HTTP; it will not run from `file://`.

## Layout

```
racer/
  src/
    race/main.gd         race controller: setup, simulation step, camera, self-test
    track/track.gd       centre line, road + barrier mesh, nearest-point lookups
    track/track_scenery.gd   markings, neon strips, lamps, skyline, start gantry
    cars/car.gd          arcade physics + model, wheel spin/steer, paint override
    cars/car_spec.gd     one car's real figures and the rules that derive game handling
    cars/car_catalog.gd  loads every spec in data/cars
    cars/ai_driver.gd    follows the racing line, brakes for corners
    items/powerups.gd    pads, boost / homing shot / mine / shock (pooled)
    fx/fx.gd             pooled particle effects, prewarmed at startup
    fx/look.gd           sky, fog, colour grade, bloom, procedural textures
    ui/hud.gd            touch controls, stats, debug toggles, settings panel
    core/settings.gd     steering sensitivity, dead zone, button size/opacity/side, camera distance (saved)
  data/cars/*.tres       car specs (add a car by adding a file)
  assets/cars/*.glb      car models, generated by tools/cars/build_cars.py
  tools/cars/            Blender script that builds the models (needs `pip install bpy`)
  scenes/main.tscn
```

## Rules the code follows

- **Data-driven cars.** Power, 0-100, top speed and drivetrain live in `data/cars/*.tres`. Game handling is derived in `car_spec.gd` (documented scale factors), never typed in per car.
- **Nothing is created mid-race.** Particle emitters, shots and mines come from pools built at startup and warmed up behind the loading cover, because a first-use shader compile is a visible hitch in a browser.
- **Simulation is separate from rendering.** `_sim_step(dt)` has no rendering dependency, so the self-test can run a whole race in seconds.
- **Models face +Z.** The Blender script builds the nose toward -Y, which exports to +Z. Wheels are separate nodes named `Wheel_FL/FR/RL/RR` with their origin at the hub. The paint is a material named `Paint`, recoloured per car in code.

## Car figures (manufacturer claims, 2025 models)

| Car | Power | 0-100 km/h | Top speed | Drive |
|---|---|---|---|---|
| Ferrari F80 | ~1,184 hp | 2.15 s | 217 mph | AWD |
| McLaren W1 | ~1,258 hp | ~2.7 s | 217 mph (limited) | RWD |
| Lamborghini Temerario | 907 hp | ~2.7 s | 213 mph | AWD |
| Chevrolet Corvette ZR1 | 1,064 hp | 2.3 s (ZTK package) | 233 mph (track-tested) | RWD |

The models are stylized low-poly cars with approximate proportions, not scans.

Done: settings panel (sensitivity, dead zone, button size/opacity, swap sides, camera distance), closer default camera, arcade driving and drift, 7 AI drivers, 4 items with particle effects, touch controls, a 22 m wide looped track, dusk-city look with bloom, four modelled cars driven by real specs, hitch logger, rotate-to-landscape prompt.
